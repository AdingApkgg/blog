平板解锁、root、刷回官方 306 之后，除了「多一个能改的机器」，还想让它做点笔记本电脑的事：LibreOffice、终端、浏览器、画画。

先说清楚这是什么：**这是 chroot，不是原生 Linux。** Android 一直在底下跑，抢内存、限 CPU，图形走 X11 转发而不是直出。轻办公能凑合，4K 剪辑和大型构建别指望。

## 三条路的取捨

- **原生双系统**（在 B 槽装 Linux）：性能最好，但要动槽位。刚解锁、刚刷完官方系统的时候，切槽的风险单独算一次，不划算。
- **Fedora + KDE**：2026 年 sheng 上确实有人做，但状态是「实验」——仓库靠 GitHub Actions 现搓 `rootfs.img`，作者十小时前还在改。要装它不是下一个 ISO 的事。
- **Termux + chroot**：全活在 `/data` 里，不碰分区，搞砸了删目录重来，`reboot` 都不一定要。

选了第三条。Debian 13 的镜像里有 KDE Plasma，`proot-distro` 只当解包器用一次，之后不再经过 proot。

## 三个决定成败的坑

这三个点不知道的人全会踩，而且踩了的现象都很像「性能不行」。

**一、必须换 Mesa。** Debian 自带的 Mesa 走 DRM `msm` 驱动，Android 内核只暴露 `/dev/kgsl-3d0`。直装官方 Mesa 的结果是 `llvmpipe` 软件渲染，KWin 卡到点不动。要换 [lfdevs/mesa-for-android-container](https://github.com/lfdevs/mesa-for-android-container) 的 kgsl 构建（支持 Adreno 740，就是给 chroot 用的），装完 `apt-mark hold`，再用 `glxinfo -B` 确认 renderer 是 `FD740 / Adreno (TM) 740`、OpenGL 4.x。只剩 `llvmpipe` 就是没成。

**二、chroot 里起 X 要按姿势。** `setenforce 0`、`TMPDIR` 指 chroot 的 `/tmp`、`XKB_CONFIG_ROOT` 指 chroot 的 xkb，并且用 `app_process` 起 X server 而不是 `termux-x11` 命令。少一个就是黑屏或 xkbcomp 报错。

**三、Termux:X11 用 sharedUid 那个 APK。** 不用的话，Android 会因为「X11 在前台、Termux 在后台」掐 Termux 的 CPU，桌面直接掉帧。代价是它只认 GitHub 签名的 Termux，F-Droid 版签名不同，装不上同 UID。

## root 给的是权限，不是调度权重

这一条最容易想错。

有 root 不等于桌面就流畅。限速和 root 是两套机制：

- `system_server` 按「这个 App 现在可不可见」把整棵进程树塞进 `top-app` / `foreground` / `background` / `cached` 的 cgroup。`su` 出来的进程仍然是 Termux 的子进程，继承 Termux 的组，`su` 不给它重新排队。
- 具体掐法是 `cpuset.cpus`（background/cached 被摁在小核）、`cpu.weight`（权重差一个数量级）、`cgroup.freeze`（进 cached 十秒后整棵进程树被冻住）。Termux 一冻，挂在它下面的 X server 一起冻，桌面定格。

所以补了一个 `05-pin-priority.sh`：解冻 `cgroup.freeze`、`cpu.weight` 抬到 1000、`cpuset.cpus` 放开全部核心、给 Termux 和 X server 打 `oom_score_adj=-900`、`renice -10`、`taskset` 钉核。

**但这是补丁不是解药。** `system_server` 每次前后台切换都会重写这些文件，切走一次再回来基本就恢复原样，得重跑。它只管抢不抢得到 CPU，止不住 freezer 在你切走的瞬间把进程冻上。

真正从头不掉组的办法是 sharedUid 那个 APK，代价在前面写了。

## 开工前的准备

- Termux 从 GitHub Releases 或 F-Droid 装，别用 Google Play（停更了）；Termux:X11 从 nightly 下。
- 两个 App 的省电策略都设「无限制」。
- 预留 15 GB 以上（KDE 装完约 4 GB）。
- USB 调试开着，出事了靠 `adb` 救。
- 需要能 `su`。

## 收尾

desktop 起来了，Chromium 能开、LibreOffice 能开、终端能用，代价是切别的 App 回来会卡一下、后台待久了会被冻。

它变成了一台「能应急的平板」，不是一台笔记本。把这个预期放在前面，剩下的都是可接受的操作成本。
