During project development, version control tools such as svn and Git are always used. As Git has developed, it has gradually been adopted by more and more people, and is even slowly replacing svn. Below we will introduce how to use Git from the aspects of **creating a Git repository, common basic Git commands, Git branch management, viewing Git commit history, Git tags, and Git remote repositories**. Of course, all the commands involved below are run in Git bash, so you must install Git first. As for how to install Git, we won't cover that here—there are plenty of installation tutorials online.

## Creating a Git Repository

There are several ways to create a git repository:

- **git init**: initialize a git repository
- **git clone**: clone a git repository

**The following describes these methods in detail**:

### 1. **git init**

Git uses the git init command to initialize a Git repository. After running git init, a .git directory is generated. This directory contains the resource data and is only generated in the root directory of the repository.

If you want to use the current directory as a Git repository, you only need to run the following command:

```bash
git init
```

The result is as follows:

![](https://img-blog.csdnimg.cn/20190731145706377.jpg)

After running this command, an .init folder is generated in the current directory, and a master branch is generated by default.

If you want to generate the repository in a specified directory, the command is as follows:

```bash
git init newDir
```

newDir is the path of the repository. After execution, a .git directory is generated under the newDir directory. The specific result is as follows:

![](https://img-blog.csdnimg.cn/20190731150209453.jpg)

After running this command, a newtest folder is generated in the current directory, and an .init folder is generated inside that folder.

### 2. **git clone**

You can use the git clone command to copy a project from a Git repository, similar to svn checkout in SVN. The command format is:

```bash
git clone <url> [directory]
```

url is the address of the git repository, and directory is the local directory. For example, to clone a certain Git code repository, you can use the following command:

```bash
git clone git://github.com/schacon/grit.git
```

After execution, the repository is generated in the current directory. If you want to generate it in a specified directory, you can append a specific path, for example:

```bash
git clone git://github.com/schacon/grit.git newgit
```

The following is the result of cloning a repository:

![](https://img-blog.csdnimg.cn/20190731154609439.jpg)

When using git clone, you can use different protocols, including ssh, git, https, etc. Among them, ssh is the most commonly used because it is faster and can be configured with a public key to avoid entering a password. The various formats are as follows:

```bash
git clone git@github.com/schacon/grit.git         --SSH协议
git clone git://github.com/schacon/grit.git          --GIT协议
git clone https://github.com/schacon/grit.git      --HTTPS协议
```

## Using Basic Git Commands

The following introduces several commonly used commands in git:

- **git config**: configuration information
- **git add**: add files to the cache
- **git status**: view file status
- **git diff**: view detailed update information
- **git commit**: commit
- **git reset HEAD**: unstage
- **git rm**: delete
- **git mv**: move or rename

**The following describes these commands in detail:**

### 1. **git config**

We can use git config to configure the username and email address, making it easier to commit code to a remote repository. The specific format is as follows:

```bash
git config --global user.name '你的用户名'
git config --global user.email '你的邮箱'
```

### 2. **git add**

The git add command can add files to the cache. For example, in a new project, it is very common to add all files, and you can use the following command:

```bash
git add .
```

Of course, we can also specify a certain type of file. For example, to add java files to the cache, you can use the following command:

```
it add *.java
```

For example, we can create two files and add them to the cache. The specific operations are as follows:

### 3. **git status**

We can use the git status command to view the status of related files. Simply run the following command:

```bash
git status
```

If there are modified files, the result is as follows:

![](https://img-blog.csdnimg.cn/20190731161735462.jpg)

According to the prompts from the git status command above, we can get three ways to handle the situation:

- Command to stage files: **git add <filename>**

- Command to discard modifications to unstaged files: **git checkout – <filename>**

- Command to stage and commit modified files: **git commit -a**

If you are fairly familiar with the various states of Git, you can also use git status -s to view abbreviated status. This abbreviated status is similar to that in SVN: M - modified, A - added, D - deleted, R - renamed, ?? - untracked, etc. If there are modified files, the result is as follows:

![](https://img-blog.csdnimg.cn/20190731161819643.jpg)

### 4. **git diff**

Run git diff to view detailed update information. Unlike git status, which only shows update status, git diff can show the specific detailed differences between changes written to the cache and modifications that have been made but not yet written to the cache.

- Changes not yet cached: **git diff**
- View cached changes: **git diff --cached**
- View all cached and uncached changes: **git diff HEAD**
- Show a summary instead of the entire diff: **git diff --stat**

For example, we modify the contents of the test.txt file and use git diff to view the detailed modification information:

### 5. **git commit**

git commit adds the contents of the cache area to the repository. You can append the -m option to provide a commit comment on the command line. The format is as follows:

```bash
git commit -m "第一次版本提交"
```

If you feel that you have to run add before every commit and want to skip the add step, you can use the -a option directly, for example:

```bash
git commit -am "第一次版本提交"
```

For example, we can create a file, add it to the cache, and then commit it. The specific operations are as follows:

### 6. **git reset HEAD**

The git reset HEAD command is used to unstage cached content. For example, if we want to unstage the committed test.txt file, we can use it as follows:

```bash
git reset HEAD test.txt
```

After execution, when you use commit again, the test.txt file will not be committed.
For example, we first modify the test1.txt and test2.txt files, then add both to the cache, then use the git reset HEAD command to restore test1.txt, and finally commit. The specific operations are as follows:

![](https://img-blog.csdnimg.cn/20190731165010729.jpg?x-oss-process=image/watermark,type_ZmFuZ3poZW5naGVpdGk,shadow_10,text_aHR0cHM6Ly9ibG9nLmNzZG4ubmV0L3F0aWFv,size_16,color_FFFFFF,t_70)

As you can see, the modified test1 file was not committed after git reset HEAD. In short, run git reset HEAD to cancel a previous git add.

### 7. **git rm**
(This is part 1 of 3 of the same post.)

If you simply delete a file manually from the working directory, running `git status` will show it under “Changes not staged for commit”. To remove a file from Git, you must remove it from the tracked file list and then commit. You can do it as follows:

```bash
git rm <file>
```

If the file was modified before deletion and has already been placed in the staging area, you must use the force delete option `-f`.

```bash
git rm -f <file>
```

If you want to remove the file from the staging area but still keep it in the current working directory—in other words, remove it only from the tracked list—use the `--cached` option.

```bash
git rm --cached <file>
```

You can delete recursively: if a directory is passed as the argument, all subdirectories and files in that directory will be recursively deleted:

```bash
git rm –r *
```

### 8. **git mv**

The `git mv` command is used to move or rename a file, directory, or symbolic link. For example, to rename a test.txt file to newtest.txt, you can use the following command:

```bash
git mv test.txt newtest.txt
```

## Git Branch Management

Almost every version control system supports branch management. Using branches, we can separate from the mainline and continue development without affecting it. Below is an introduction to the commonly used branch commands in Git:

- **git branch**: Command to list branches
- **git branch (branchname)**: Command to create a branch
- **git checkout (branchname)**: Command to switch branches
- **git merge**: Command to merge branches
- **git branch -d (branchname)**: Command to delete a branch

**The following sections describe these commands in detail:**

### 1. **git branch**

`git branch` can both list branches and create branches. With no arguments, `git branch` lists your local branches; with an argument, `git branch` creates a branch with that name.

To list branches, the command format is as follows:

```bash
git branch
```

The effect when executed in bash is shown in the following figure:

![](https://img-blog.csdnimg.cn/20190731113408345.jpg)

When we want to create a branch, we can add an argument after it. The command format is as follows:

```bash
git branch  branchname
```

Now we can see that there is a new branch, test. As for the master branch, when we run `git init`, Git creates the master branch for you by default.

### 2. **git checkout (branchname)**

`git checkout` can switch branches. The command format is as follows:

```bash
git checkout branchname
```

If we want to switch to the test branch just created above, we can do the following:

We can also use the `git checkout -b (branchname)` command to create a new branch and immediately switch to it, so that we can work in that branch. For example, if we want to create a newtest branch and switch to it after creating it, we can do the following:

### 3. **git merge**

The `git merge` command can merge any branch into the current branch. The command format is as follows:

```bash
git merge branchname
```

## Git Tags

Tags make it easy to permanently remember a particular commit snapshot. For example, when we release a new version, we can give it a "vx.x" version number by tagging it with `git tag`.

**Creating a new tag**

You can create a tag with **git tag -a vx.x**. The `-a` option means "create an annotated tag". You can also run it without `-a`, but then Git will not record when or by whom the tag was created, and it will not let you add a tag annotation.
For example, let's create a tag for the example above:

**Appending a tag**

If we forget to tag a commit and have already published it, we can append a tag afterwards. For example, suppose we released commit d6f7147 but forgot to tag it at the time. We can still do it now:

![](https://img-blog.csdnimg.cn/20190801153352398.jpg)

**Viewing tags**

If we want to view all tags, we can use the following command:

```bash
git tag
```

The result looks like this:

![](https://img-blog.csdnimg.cn/20190801153532294.jpg)

Command for specifying tag information:

```bash

```

Command for a PGP-signed tag:

```bash
git tag -s <tagname> -m "某某标签"
```

## Git Remote Repositories

The Git commands we have used so far all run locally. If you want to share your code through Git or collaborate with other developers, you need to put the data on a server that other developers can connect to. This section uses GitHub as the remote repository to introduce how to use Git remote repositories.

Here are several commonly used remote repository commands:

- **git remote add**: add a remote repository
- **git remote**: view the current remote repositories
- **git fetch**, **git pull**: fetch from a remote repository
- **git push**: push to a remote repository
- **git remote rm**: delete a remote repository

### 1. **git remote add**

`git remote add` adds a remote repository. Its command format is as follows:

```bash
git remote add [alias] [url]
```

The `[alias]` parameter is the alias, and `[url]` is the address of the remote repository. For example, we can add the https://github.com/qtqt/test.git repository locally and name it test, as follows:

![](https://img-blog.csdnimg.cn/20190801164530171.jpg)

### 2. **git remote**

`git remote` shows the current remote repositories. The result looks like this:

![](https://img-blog.csdnimg.cn/20190801164618710.jpg)

As you can see, it includes the repository with the alias test added above.

### 3. **git fetch**, **git pull**

**git fetch** can fetch data from a remote repository. If there are multiple remote repositories, we can append the repository alias, as follows:

![](https://img-blog.csdnimg.cn/20190801164810212.jpg)

After this command finishes, you need to run `git merge` to merge the remote branch into your current branch. Suppose you have configured a remote repository and want to fetch updated data. You can first run `git fetch [alias]` to tell Git to fetch data that it has and you do not, and then run `git merge [alias]/[branch]` to merge any updates on the server (assuming someone has pushed to the server at this point) into your current branch. The operation is as follows:

![](https://img-blog.csdnimg.cn/20190801164855388.png)

After it finishes, you can find the remote repository's files in your local repository. This approach only works if the local repository is empty; if it is not empty, you will get the error: `fatal: refusing to merge unrelated histories`.

The **git pull** command fetches from another repository or local branch and integrates it. In the default mode, `git pull` is shorthand for `git fetch` followed by `git merge FETCH_HEAD`. Its usage is:

```bash
git pull [options] [<repository> [<refspec>…]]
```

For example, we can pull the remote repository locally. If the local repository and the remote repository are actually two independent repositories, the `--allow-unrelated-history` option resolves the issue.

![](https://img-blog.csdnimg.cn/20190801172317820.png)

The difference between **git fetch** and **git pull**:

1. `git fetch`: essentially fetches the latest version from the remote to the local repository and does not merge automatically.
2. `git pull`: essentially fetches the latest version from the remote and merges it into the local repository.

### 4. **git push**

`git push` pushes your new branch and data to a remote repository. Its format is as follows:

```bash
git push [alias] [branch]
```

For example, we can push the files committed earlier to the remote repository:

### 5. **git remote rm**

`git remote rm` deletes a remote repository. Its format is as follows:

```bash
git remote rm [别名]
```
